## Design the learning before the result exists.

Three synthetic covenants bind the UK Government Transformation Engine’s held dossiers. They make questions, contrasts, measures, guardrails, distribution, missingness, affected-party obligations, interpretation and publication rules explicit—without collecting data, running an evaluation, selecting an option or creating authority.

Every design and the publication as a whole are exactly:

- `DRAFT`
- `UNSEALED`
- `UNREGISTERED`
- `NO-RUN`
- `NO-RESULT`
- `NOT-APPROVED`

This is an independent assisted design publication. Exact text has not been separately human-reviewed. It is not government, a Trial Chamber plan, a registered protocol, ethics approval, analytical assurance, an evaluation, a result, advice, a decision, adoption, or permission. It does not create authority.

## What is here

The producer is zero-dependency, deterministic, offline, and read-only except for one fixed build output:

- `data/config.json` — product, URL, boundary, lineage, freshness, and separation contract.
- `data/designs.json` — compact authoring records for exactly three synthetic designs.
- `data/sources.json` — exactly ten official method/governance links with a strict non-evidence firewall.
- `vendor/` — exact frozen Transformation and transitive Government receipts used only as synthetic design context.
- `schemas/v0.1/public-snapshot.schema.json` — the sole closed Draft 2020-12 public schema.
- `public/evaluation-covenants.json` — the deterministic expanded public snapshot.
- `EVALUATION-COVENANT-v0.1.md` — the human guide and interpretation contract.

The three designs concern:

1. Four-nation information orientation.
2. HMRC notice-route orientation.
3. Public-money category orientation.

They do not contain live data, people, participants, feedback, datasets, results, estimates, amounts, thresholds, selected options, rankings, actions, tools, runners, forms, accounts, or submission surfaces.

## Commands

Node.js 20 or later is required. No package installation or network access is needed.

```sh
npm test
npm run validate
npm run build
npm run build:check
npm run check
npm run overview
```

- `validate` checks exact input bytes and canonical receipts, lineage, schema, and semantic holds without writing.
- `build` deterministically replaces only `public/evaluation-covenants.json` through an atomic fixed-path writer.
- `build:check` proves the checked-in public artifact is byte-identical to a fresh deterministic build.
- `check` performs JavaScript syntax checks and the immutable build check.
- `overview` prints a bounded, non-result summary.

There is no runtime fetch, clock read, LLM, MCP surface, server, POST route, runner, or free-text input.

## Trial Chamber separation

The Trial Chamber asks how a bounded artifact might someday be tested. The Evaluation Covenant asks what learning about a synthetic intervention would mean, for whom, under which contrast, and under which publication obligations. Neither runs.

This producer creates no referral, evaluation request, evaluation plan, fixture, criterion rule, resource envelope, preflight, execution authority, runner, artifact pin, trial run, or result. `trialChamberPlanRefs` is exactly empty.
